# ADR-0014: Canvas Gutter Routing, Lineage Focus, and Scoped Theme Parity

- **Status**: Accepted
- **Date**: 2026-09-10
- **Deciders**: Architect, Frontend Lead, Core Maintainers
- **Informed**: All Web Users, Multi-Session Operators

---

## 1. Context and Problem Statement

### 1.1 Background & Visual Friction
协作看板（ADR-0012, ADR-0013）上线后，在多会话并发与黑板协同场景中暴露出三项直观视觉缺陷：
1. **连线穿透会话卡片文字**：黑板归属边（`author-edges`）直接以二次贝塞尔曲线连接会话顶部与黑板底部。在同一工作区列内，下层会话的连线直接纵向穿透上方所有中间会话卡片与文字；跨会话调用边在同列跨层相连时亦存在类似文字穿越穿透。
2. **全量连线导致视觉噪点**：所有静态黑板归属线与历史调用线全量常态高亮绘制，缺乏主次层级，造成视觉噪点与信息杂乱。
3. **单向暗色锁定与切换入口缺失**：画布 CSS 样式全量硬编码深色色值，DSH 宿主在浅色主题下看板出现白底嵌黑块的失调；同时看板顶栏缺少直观的明暗切换快捷按钮。

## 2. Decision Outcome

我们确立以下四项设计与渲染规范：

### 2.1 外侧通道走线与右出左进几何模型（Gutter Routing & Right-Exit Left-Enter）
1. **端口进出规范**：调用发起端或黑板发布端统一由节点右侧引出（Outbound）；调用接收端统一由节点左侧接入（Inbound）。
2. **专属走线通道**：在工作区列左右外侧预留走线通道（Gutter Channels）。连线出节点后直接进入外侧通道，在通道内纵向穿行避开所有中间会话节点，到达目标高度后横向折入，严禁穿透任何会话包围盒。
3. **黑板发布走线**：由发布会话右侧引出进入右侧通道，纵向直达工作区顶部外边缘后，折线/曲线斜向接入顶部黑板对应条目底部中点。
4. **跨工作区反向走线**：右侧工作区调用左侧工作区时，连线自发起节点右侧引出后进入右走线通道平滑折返，通过列间空隙向左横穿并接入目标节点左侧。

### 2.2 链路聚焦与常态降噪（Lineage Focus & Noise Suppression）
1. **默认低噪呈现**：依据 WCAG 2.1 AA 视觉对比度与看板可读性要求，静态黑板发布归属线默认保持低噪呈现（0.50 细虚线），非活跃历史调用线淡化至低对比度（0.30），活跃调用线保持动态流动发光；在用户悬停（Hover）或点击选中某一实体时，高亮激活聚焦链路（1.00 实线与脉冲发光）。
2. **按需链路点亮**：当鼠标悬停（Hover）或点击选中（Select）某一会话或黑板条目时，高亮激活与其直接相关的上下游关联链路。

### 2.3 严格插件作用域主题适配（Scoped Theme Parity）
1. **宿主接口映射**：看板工具栏右侧增加明暗模式切换按钮（深色显太阳，浅色显月亮）。按钮点击仅作为 DSH 宿主 `ctx.theme.setTheme` 接口的映射触发。
2. **严格作用域隔离**：深色与浅色样式全部收敛在 `.dsh-canvas-container` 及其子类选择器内，基于 `body[data-ds-dark-theme]` 与 DSH 语义变量（`--dsw-alias-*`）自适应渲染，严禁向插件作用域外注入全局样式。

### 2.4 工作区列布局几何与头间距不变量（Workspace Column Geometry & Clearance）
1. **工作区列起始与头部尺寸**：工作区列纵向起始点为 $startY = 150\text{px}$；列头部胶囊包围盒位于相对坐标 `(12, 10)`，高度为 $38\text{px}$，其底边绝对坐标为 $startY + 10 + 38 = 198\text{px}$。
2. **严格 16px 头间距不变量**：依据 `DESIGN.md` 标准留白规约（`spacing-4 = 16px`），工作区头部底边与首个会话卡片顶边之间必须保持严格的 $16\text{px}$ 正向净间距，首卡片顶边绝对坐标固定为 $198 + 16 = 214\text{px}$。
3. **会话节点中心垂直坐标推导**：会话卡片垂直半轴为 $ry = 26\text{px}$，行间距步长为 $72\text{px}$。首个会话节点垂直中心必须由布局原点推导而来：
   $$sessionStartY = startY + 10 + 38 + 16 + 26 = startY + 90\text{px}$$
   第 $i$ 个会话节点的垂直中心为 $centerY = sessionStartY + i \times 72\text{px}$。严禁将首节点中心硬编码为错误切入头部的数值（如历史缺陷值 $214\text{px}$）。

## 3. Consequences

### 3.1 Positive
- 消除连线穿越会话卡片文字的问题，拓扑走线规整清晰。
- 常态降低非聚焦连线视觉干扰，交互时突出关联链路。
- 完整支持浅色与深色主题切换，且严格遵守宿主插件边界与零污染原则。

### 3.2 Negative & Mitigations
- 弯折连线计算稍有增加，通过固定通道坐标偏移与平滑三次贝塞尔结合，保持渲染性能。
