# ADR-0020: System Performance Specifications, Resource Budgets, and Deterministic SLA Baselines

- **Status**: Accepted
- **Date**: 2026-09-18
- **Deciders**: Architect, Engineering Team, Core Contributors
- **Consulted**: Systems Performance Ops, QA Automation Lead, Frontend Lead
- **Informed**: All DSH Developers, Core Maintainers, Subagents

---

## 背景

### 现状
插件作为宿主进程内的会话协作扩展，贯穿了公共黑板持久化共享、单播调用与同级会话调度以及网页看板全景观测三大子系统。

随着多智能体协作与多工作区运行场景的增加，系统面临潜在的性能漂移与退化风险：
1. 事件循环阻塞风险：单主线程模型下，若黑板内存查询或拓扑数据序列化出现高耗时，将直接导致宿主事件循环卡顿，影响主智能体的实时交互；
2. 并发写磁盘抖动与锁竞争：多智能体并发发布黑板条目时，若防抖与原子重命名机制缺少耗时与聚合约束，容易在弱输入输出或文件扫描环境下引发竞争与锁冲突；
3. 前端渲染卡顿与资源消耗：网页看板在 50 节点以上拓扑下的矢量走线重算若耗时超过 16ms 会导致丢帧，后台标签页常驻轮询持续消耗计算资源；
4. 缺乏量化防御基线：此前虽然各模块具备防抖、配额与截断实现，但缺少系统级的量化性能预算与确定性回归门禁。

### 约束
- 事件循环纪律：所有纯内存操作在个位数毫秒内完成，不得阻塞宿主事件循环；
- 资源边界受控：进程内各级缓存与状态结构具备明确上限，长期常驻内存增量严格可控；
- 非侵入可观测性：网页看板与调用记录聚合严格保持只读，自身开销不得扰动核心调度业务；
- 门禁稳定可靠：性能门禁测试兼顾严格量化与测试稳定性，具备对慢速运行环境的防抖动冗余。

---

## 动因

- 确定性延迟指标：为黑板读取、单播投递、调用记录路由制定量化延迟上限；
- 输入输出聚合与原子性：严格落实 300ms 防抖合并落盘，单次原子重命名与备份同步控制在 50ms 内；
- 内存容量有界：固化黑板 200 条与调用记录 200 条上限及状态感知淘汰规则，限定插件常驻内存增量不超过 30MB；
- 渲染流畅与节流轮询：保障大规模块下单帧计算不超过 16ms，确立前台 1500ms、后台 5000ms、长时间隐藏完全挂起的节流策略；
- 门禁集成把关：新增可执行的性能基准测试，纳入发布验证核心门禁。

---

## 方案

### 方案一
仅在文档中定性要求注意性能与避免耗时循环，不设定具体毫秒指标和容量数字。
- 弊端：无法防御代码重构带来的隐式性能回归，无法在持续集成中自动化判定合格。

### 方案二
设定极度苛刻的微秒级指标并施加硬断言。
- 弊端：在慢速或虚拟化运行环境中极易因宿主资源抖动引发非预期测试失败。

### 方案三
确立工程务实、可测量的分级延迟与容量基准，测试门禁采用预热加中位数采样，并预留三倍防抖阈值。
- 收益：既提供清晰严格的架构设计红线，又保障工程验证的确定性与稳定性。

---

## 决策

采纳方案三：建立全链路务实性能预算与三倍防抖容差验证。

### 原则

#### 黑板性能
- 读取延迟：检索 100 条条目，纯内存操作耗时 99 分位不超过 5ms；
- 防抖合并：连续突发写入必须在 300ms 防抖窗口内合并为单次落盘，严禁每次写立即触盘；
- 落盘耗时：单次临时文件写入、原子重命名与备份同步耗时不超过 50ms。

#### 调度性能
- 单播分发：进程内事件投递与调度确认耗时 99 分位不超过 2ms；
- 目录检索：会话目录全量扫描与过滤耗时 99 分位不超过 10ms；
- 配额拦截：单工作区并发运行根会话达 5 个并发运行配额，或代际深度超标、频控超限时，拦截判定为同步阻断，耗时不超过 1ms。

#### 看板性能
- 路由聚合：快照聚合与序列化耗时 99 分位不超过 20ms；
- 渲染流畅度：单画布在 50 会话节点与 100 条调用连线规模下，单次通道分流走线与布局计算耗时不超过 16ms；
- 轮询节流：前台激活保持 1500ms 间隔轮询，后台或失焦自适应降频至 5000ms 间隔，页面隐藏超过 5 分钟后完全挂起定时器，切回前台立即触发一次抓取并恢复轮询。

#### 容量预算
- 黑板容量：硬上限 200 条，单条正文内容截断 64KB；
- 淘汰优先级：满额写入时执行确定性状态感知淘汰，按已过期、已撤销、最早创建的活跃条目顺序淘汰；
- 调用记录环形缓冲区：容量上限 200 条，单条摘要截断 120 字符，完整正文截断 8192 字符；
- 内存预算：插件全量运行时在长周期压测下的常驻内存增量预算上限不超过 30MB。

## 收益

### 收益
- 建立完备可量化的系统性能边界，明确各模块的性能职责；
- 防抖合并与状态感知淘汰机制有效防止高并发下的磁盘输入输出过载与内存泄漏；
- 降频轮询与挂起机制降低看板页面长时间开启时的客户端资源占用；
- 门禁自动化确保性能退化在提交阶段即可被直接拦截。

### 权衡
性能测试包含少量延迟采样，测试总时长轻微增加约 300ms；黑板淘汰策略会丢弃超出容量的数据，优先淘汰过期和撤销条目以保护有效业务上下文。

---

## 验证

### 测试套件
自动化测试覆盖各项性能指标：
1. 黑板性能：验证 100 条数据读取耗时中位数、50 次并发写合并为单次原子落盘，以及状态感知淘汰顺序；
2. 调度与配额：验证单播调用内存调度耗时中位数、会话目录全量扫描耗时中位数与配额超额同步拦截耗时；
3. 看板路由与内存：验证调用记录快照序列化耗时中位数与常驻内存增量预算；
4. 客户端降频：验证前台、后台与长时间隐藏的状态转换与定时器挂起逻辑。
