# ADR-0022: Verifiable Architecture Topology Artifacts and Agent Discipline Decoupling

- **Status**: Accepted
- **Date**: 2026-09-18
- **Deciders**: Architect, Engineering Team, Documentation Maintainers
- **Consulted**: Multi-Agent Ops, System Performance Team
- **Informed**: All Plugin Contributors, Downstream Subagents

---

## 背景

### 现状
随着系统演进为覆盖前端看板、进程内单播分发、公共黑板状态存储与宿主端会话调度的多子系统架构，团队需要对全局拓扑进行端到端可视化与架构归档。在此过程中暴露出两项结构性阻抗：

1. 预提交门禁目录白名单过于死板：此前钩子脚本配置了仅放行文档子目录的硬性白名单，可验证架构规范源文件与离线交互式单文件交付物缺少合法存放路径，导致提交被门禁无条件拦截；
2. 智能体文风治理规范与加载层级错位：此前在 ADR-0009 中记录了文档防注水、去表情符号、去伪学术黑话与四字子标题规范。然而依据信息阶梯理论，架构决策记录属于按需惰性读取内容，智能体在常规会话中不会主动加载，导致文风规范在运行态对大语言模型失效。

### 约束
- 可验证拓扑基线：架构图表必须具备机器可验证性，严禁提交未经检验的手写草图；
- 零痕迹版本库卫生：自动化测试产生的临时快照与检测报告不得污染版本控制仓库；
- 信息阶梯层级重构：对智能体的行为、文风与输出纪律必须驻留在常驻上下文 AGENTS.md，而架构决策记录仅作为历史决策证据。

---

## 动因

- 合法收容架构资产：在架构专属目录下合法收容机器可验证的架构源定义与交互式单文件交付物；
- 预提交白名单对齐：修正预提交钩子白名单正则，在保持严格防御的同时放行架构目录；
- 运行态纪律常驻：将客观平实、纯文本无括号注解、四字子标题、对齐领域词汇等运行态纪律由 ADR-0009 提炼沉淀至根目录 AGENTS.md，确保每轮推演无条件生效；
- 历史决策档案解耦：明确决策记录目录纯粹作为架构决策历史档案，消除试图以历史决策记录约束大模型实时交互的认知偏差。

---

## 方案

### 方案一
将架构图视作临时产物存入临时工作目录。
- 弊端：丢失版本控制能力，无法作为团队统一审阅与随代码演进的架构资产。

### 方案二
在系统提示词中强制智能体每轮读取 ADR-0009。
- 弊端：严重消耗上下文容量，引发额外文件读取时延，且容易因注意力稀释导致执行不稳定。

### 方案三
预提交白名单放行架构目录，同时将运行态纪律沉淀至 AGENTS.md。
- 收益：架构资产具备完整的版本追踪与门禁保障；临时副作用通过忽略文件干净隔离；智能体文风约束即时在根目录全局生效，解决决策记录无法约束模型实时输出的问题。

---

## 决策

采纳方案三：预提交白名单放行架构目录并将运行态纪律沉淀至根目录常驻规范。

### 决策项
1. 白名单放行：预提交钩子正则更新为允许架构目录；
2. 测试副作用忽略：版本忽略规则追加临时视觉检测文件排除；
3. 输出纪律提炼：在根目录 AGENTS.md 设立专属章节，作为智能体运行态常驻准则；
4. 决策档案解耦：ADR-0009 追加不变量说明，明确其作为历史决策证据的定位，操作执行委托至 AGENTS.md。

---

## 收益

### 收益
- 系统架构图成为仓库第一公民，具备静态约束检查门禁；
- 智能体输出文风具备常驻硬约束，即时生效且不依赖外部文件读取；
- 厘清对决策记录消费机制的定位，符合标准工程信息阶梯。

### 权衡
架构变更时需同步重新运行校验并交付单文件产物。
